# IM：在聊天软件里和智能体说话

- 入口：**设置 → IM**（桌面端标签页；移动端 `设置 → IM` 独立一页）
- 代码：`backend/app/im/`（域）· `frontend/src/components/ImSettings.tsx`（桌面）
  · `frontend/src/mobile/pages/MobileImPage.tsx`（移动端）
- 参考实现：DS Bot（`Fei2411/DS-Bot`）的 IM 设置页与平台适配器 —— 只借鉴交互与协议思路，
  代码按本仓库的分层重写（Python · FastAPI · 无前端框架）。

## 为什么

用户离开电脑时，智能体还在干活，但只有回到控制台才能找它。大多数人整天开着 Telegram、
飞书、钉钉这类聊天软件。IM 让用户在那里和某个智能体对话。

取舍：

- **IM 是通道，不是成员。** 聊天软件里的机器人绑到一个智能体，不进智能体名单、不占权限。
  用户在 IM 里说的话就是用户的话，进那个智能体当前的那段对话。
- **平台侧只往外连。** 只用长连接 / 长轮询（Telegram `getUpdates`、飞书 / 钉钉 / 企业微信 /
  Discord / Slack 的 WebSocket、QQ Gateway），**不需要公网地址、不开放端口**。
- **只有服务运行时才收发消息。** 服务停了，平台会保留（或不保留）消息；能收到的等下次启动。

## 支持的平台

| 平台 | 连接方式 | 要填的 | 私聊 | 群 | 卡片按钮 |
| --- | --- | --- | --- | --- | --- |
| Telegram | Bot API 长轮询 | Bot token | ✓ | @ 机器人 / 回复它 | ✓ |
| 飞书 / Lark | 长连接（protobuf 帧） | 版本、App ID、App Secret | ✓ | @ 机器人 | ✓ |
| 钉钉 | Stream 模式（WebSocket） | Client ID、Client Secret | ✓ | @ 机器人 | ➖（回编号） |
| 企业微信 | 智能机器人长连接 | Bot ID、Secret | ✓ | @ 机器人 | ✓ |
| QQ | 官方机器人 Gateway | App ID、App Secret | ✓ | @ 机器人 | ➖（回编号） |
| Discord | Gateway（WebSocket） | Bot token | ✓ | @ 机器人 | ✓ |
| Slack | Socket Mode | App-Level Token、Bot Token | ✓ | @ 机器人 | ✓ |
| 微信（个人号） | — | — | 暂不支持 | — | — |

「微信个人号（iLink 扫码）」只在平台清单里作为**即将支持**展示：扫码登录依赖未公开的
第三方协议，企业场景请用企业微信。

## 行为

### 添加与绑定

- 设置 → IM：列出已添加的机器人，每个一行：平台、账号名、状态（已连接 / 连接中 / 重试中 /
  连不上及原因）、绑定的智能体。
- 添加：选平台 → 填字段 → 选智能体 → 连接。**保存前先向平台核对一次凭据**，核对不通过不保存。
- 一条连接绑一个智能体：所有私聊都进它。改绑定、停用、重试、移除都在这一行里。
- 平台凭据按字段加密落库（`app.security`），接口只回「哪些字段已填」；移除连接时一起删掉。

### 配对：只认允许过的账号

- 一个账号第一次发消息（私聊，或在群里 @ 机器人）：设置页出现「谁想连接」，带平台上的名字。
  点「允许」才算配对；点「拒绝」就去掉这条请求。
- 没配对的账号：消息不进任何智能体，机器人只回一次「已发出连接请求」。
- 群里没 @ 机器人的消息**完全忽略**（不打扰、也不进智能体）。
- 配对过的账号可以在设置里移除，之后它的消息不再进智能体。

### 消息怎么走

- 私聊：消息进绑定智能体当前的那段对话（与网页发消息同一条运行链路：排队、取消、
  工具调用、落库全一致）。
- 群：@ 机器人的那条消息去掉 @ 后进群绑定的智能体（没单独指定就用连接绑定的那个）。
- 图片按图片发给智能体；文件按附件发给智能体（落到对话工作目录的 `attachments/`）。
- 一条聊天固定一条对话（`im_chats.conversation_id`），上下文连续；换绑智能体后新建一条对话。
- 同一聊天的消息串行：上一条还在跑时先回一句「排在后面」，等这一轮结束再进智能体。
- `/stop` 停下这个聊天正在跑的那一轮；`/start` 回一句「我是谁」。

### 什么发回聊天软件

- 默认只发**这一轮运行的正文**（`message.delta` 拼起来的文本）。
- **过程内容是可选设置**（在连接详情里逐条开关，默认全关）：思考过程、工具调用、日志。
  打开后它们以引用块（`> 💭` / `> 🔧` / `> ↩️`）附在正文之后，与回答明确分开；
  单行截断到 400 字符，避免一个工具输出把整条消息撑爆。
- 只发给发起这一轮的那个聊天；网页 / 手机 / 定时任务触发的轮次不往聊天软件外发。
- 平台单条长度上限按平台切分（Telegram 4096、Discord 2000、QQ 2000、Slack 4000、
  飞书 / 企业微信 4000、钉钉 5000、微信 1800）；尽量在段落 / 代码块边界断开。
- 发送失败：平台明确拒绝的（凭据失效、超出回复窗口）不重发，原因显示在那一行；
  网络类失败按退避重试 4 次，仍失败同样显示原因 —— 一条发不出去的消息不会卡住后面的。

## 分层

```
app/im/api.py（路由：参数校验 / 归属过滤 / 状态码）
      │
im/service.py（连接登记表 · 配对 · 聊天绑定 · 发送队列 · 启停与重连）
      │                    │
im/bridge.py          im/platforms/*（各平台收发，叶子层）
（与对话域的唯一边界：  ↑ 只依赖 im/base.py、im/format.py、im/crypto.py、
  prepare_run/start_run）  httpx、websockets
  prepare_run/start_run）
      │
runtime/service.py（对话域：排队、执行、落库）
```

- **「某个平台怎么收发消息」是适配器的知识**：新增一个平台 = 在 `im/base.py` 的
  `PLATFORMS` 加一条元数据（表单由它生成）+ 在 `im/platforms/` 加一个适配器并注册。
  接口层、前端表单都不需要改。
- **适配器是叶子节点**：不得 import `app.api.*` / `app.runtime.*` / `app.db` /
  `app.models`。企业微信的媒体解密（AES-256-CBC）收在 `im/crypto.py`，适配器不直接
  import `cryptography`。
- **与对话域只有一个交界**（`bridge.py`）：IM 消息写成一条普通用户消息，跑完把回复发回去；
  IM 这一层不知道任何智能体或内核的细节。
- **状态只落库**：连接状态写 `im_connections.last_status` / `last_error`，设置页轮询它，
  运行时对象不外泄给接口层。
- **连接级小状态**（Telegram 的 update 游标等）放 `im_connections.runtime`（JSON），
  重启后恢复，不会把旧消息再回一遍。
- **连接级开关**（发什么）放 `im_connections.options`（JSON）：键固定为
  `show_thinking` / `show_tools` / `show_logs`，缺省一律 False；新增开关要在
  `im/base.py` 的 `OPTION_KEYS` 里登记，接口与两端界面都按它读写。

## 不做什么

- IM 机器人不进智能体名单，不派活（那是协作域的事）。
- 不让没配对的人和智能体说话；不把群里其他人的话转给智能体。
- 不在聊天软件里填密钥、改设置。
- 不接需要公网回调地址的接口。

## 已知限制

- 微信个人号暂不支持；QQ / 钉钉的被动回复有平台时限，超时后用户再发一句即可恢复。
- 钉钉、QQ 没有卡片按钮：提问 / 审批用「回复编号」（当前 IM 里只外发正文，卡片见下条）。
- 提问卡 / 审批卡暂不外发到 IM（正文与 `/stop` 已覆盖日常使用）；后续可在
  `bridge` 里接上 `collab` / 对话域的卡片事件。
- 过程内容是**连接级**开关（不是全局）：同一个平台可以接两条连接，一条安静、一条详细。
- 电脑关机或睡眠时收不到消息；服务重启后连接会自动重连。
